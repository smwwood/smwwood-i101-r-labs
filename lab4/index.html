Part 3

Turning words into data

Now we'll make new logical variables that reveal whether particular words appear in descriptions.

Our detective strategy

Choose a word, search every complaint description, save the TRUE/FALSE result in a new column, then count the TRUE values.

A new column doesn't replace the old description: it adds information to the same dataset.

1 · Choose a word2 · Search3 · Save logical4 · Count matches
Watch

We will use a new function called grepl() to search for specific words in the complaint descriptions. grepl() is a funny name because it's actually an acronym for "Global Regular Expression Print List". Global means it searches the entire string, Regular Expression means it can match patterns, Print List means it returns a list of TRUE/FALSE values (based on whether it found the target pattern).

The way we use grepl() is by providing it with the word we want to search for, the column of text to search in, and optionally setting ignore.case=TRUE to make the search case-insensitive (e.g., "i love scooters" could match "I Love Scooters").

Part 4

Two datasets are better than one

What happens when scooter activity and resident complaints join forces?

Our research question

Do months with more scooter trips also tend to have more complaints?

Activity dataset

Multiple providers and dates, with trip totals and available scooters.

Complaints dataset

One row per report, with its date and text.

We cannot simply join those original rows: they don't represent the same thing. The rows in our original scooter activity dataset represent a combination of provider and date. The rows in our complaints data represent individual reports. In order to join them together, we need to make versions of each table that have the same row unit. We will use the year_month column as the common row unit. We will first summarize each table to one row per year-month, then join on the shared year_month value.
